# Story 相册齐行画廊布局设计

## 背景

当前 Story 相册使用固定四列网格。每张照片被限制在相同列宽中，导致宽画幅照片显示面积偏小；桌面端的受控错位也让每行节奏不够稳定。参考图更接近当代摄影展墙：相框更宽、照片占比更高，每行保持秩序并整体居中。

本次改造只针对 Story 页面相册展示层，不改变 Gallery 首页、照片数据、图片派生、CDN、灯箱数据源和其他页面。

## 目标

- 照片更大，尤其是宽画幅照片不再被固定列宽压缩。
- 相框具有更明确的金属边、卡纸层和轻微悬浮感。
- 每行整体居中，取消当前刻意的上下错位，建立更稳定的展墙秩序。
- 从固定列宽切换到固定目标行高，宽度由原始画幅比例自然决定。
- 保持 4:3、竖幅、宽画幅混排时的可读性和响应式稳定性。
- 保留已确认的图标返回入口与 PhotoSwipe 交互。

## 非目标

- 不更改 Story 的照片顺序。
- 不更改 thumb.webp 首屏加载和 large.avif 灯箱加载逻辑。
- 不新增图片纹理、图片资源或 CDN 对象。
- 不恢复顶部导航或 Story 评论。
- 不改变 Gallery 首页卡片布局。
- 不改变 PhotoSwipe 的关闭按钮、箭头、序号和循环策略。

## 设计决策

### 1. 布局模型：固定目标行高 + 画幅自然宽度

相册从 CSS Grid 改为可换行的 Flex 行布局：

- 相册容器使用 display: flex、flex-wrap: wrap、justify-content: center。
- 每个相框使用固定的响应式目标高度。
- 相框宽度由 --story-photo-ratio 和目标高度自然计算。
- 行内项目从左到右保持 Markdown 中的照片顺序。
- 行内项目不足以填满版心时，整行保持居中，不拉伸最后一行。
- 当一行的自然宽度超过容器时，Flex 自动换行；不压缩宽画幅，不产生横向溢出。
- 删除当前桌面/平板 offset token 和 translateY，所有行回到同一基线。

这是一种 CSS 原生的齐行画廊，不引入基于 viewport 测量的运行时布局计算。照片比例已经存在于相框的 CSS 自定义属性中，因此不需要复制照片元数据，也不会引入 SSR 与 hydration 的尺寸差异。

### 2. 版心与目标行高

展墙使用更宽的版心，让照片和相框真正占据画面：

| 视口 | 相册最大宽度 | 目标相框高度 | 横向间距 | 行间距 |
| --- | --- | --- | --- | --- |
| ≥ 1200px | min(1400px, calc(100vw - 64px)) | 220px | 24px | 32px |
| 720–1199px | min(1120px, calc(100vw - 48px)) | 185px | 20px | 28px |
| < 720px | calc(100vw - 32px) | 140px，允许 max-width: 100% | 12px | 22px |

目标高度是行节奏的控制值，不是给图片裁切的高度。相框保持原始画幅比例，图片使用 object-fit: cover，因此宽画幅会在同一行中自然获得更大的宽度。

移动端不再强制两列。宽画幅在自身自然宽度超过可用空间时单独换行，竖幅和 4:3 照片则根据自然宽度形成稳定的两列或一列组合。

### 3. 相框材料

每个相框由三层组成：

1. 深石墨金属外框：约 3px，使用克制的深浅渐变体现细微金属边界。
2. 博物馆白卡纸：桌面 24–28px 的内缩，平板 20–24px，移动端 10–12px。
3. 照片层：保持原始比例，带一圈极细的内侧边界。

阴影使用两层：

- 一层贴近相框底部的接触阴影，建立相框与墙面之间的距离。
- 一层向右下扩散的柔和阴影，强化悬浮感。

不使用圆角、木纹、厚重 bevel、全出血图片或明显的 hover 位移。hover 只降低图片亮度，保持展墙静态感。

### 4. 标题、展签和返回

- 标题、日期、地点和简介继续左对齐。
- 标题与简介最大宽度为 min(620px, 100%)，与宽展墙版心形成“窄文字、宽相册”的层次。
- 展签只保留一条约 48px 的细横线和小号灰黑色文字。
- 展签不显示序号，不使用卡片底板、圆角或阴影。
- 返回入口继续使用居中的图标，不显示文字；保留 aria-label 和 title 作为可访问名称。

### 5. 灯箱不变项

PhotoSwipe 继续保持当前已确认行为：

- 右上角关闭按钮隐藏。
- 左右箭头靠近视口边缘，不覆盖图片内容。
- 序号位于左上角。
- 到首尾后不循环。
- 保留原始照片比例、thumb 到 large 的资源切换和现有修饰键点击行为。

## 组件边界与数据流

### StoryAlbum.vue

负责：

- 根据 ids 保持照片顺序并过滤不存在的 id。
- 为每个相框输出 --story-photo-ratio: width / height。
- 输出 thumb.webp 图片、无障碍标签、caption 关联和 large.avif 链接。
- 输出图标返回入口。
- 继续把照片索引交给 PhotoSwipe。

不负责：

- 读取 viewport 宽度。
- 在运行时测量容器或执行行分组。
- 把布局宽度写入照片 manifest。

### _gallery.scss

负责：

- Flex 换行与行内居中。
- 三档目标行高、版心和间距。
- 相框、卡纸、照片边界、阴影和展签视觉层。
- 移除旧的 offset transform 视觉规则。

### 测试

- StoryAlbum 组件测试继续锁定照片顺序、thumb.webp、large.avif、原始比例、caption 无障碍关系、图标返回和 PhotoSwipe 索引。
- 样式断言锁定 Flex 行布局、justify-content: center、三档目标高度、无 transform、相框边框/卡纸/阴影和展签横线。
- PhotoStoryHeader 测试锁定 620px 阅读列和宽屏 1.75 行高。
- 生产构建与静态预览验证 1440px、820px、390px 三种视口。

## 验收标准

### 桌面 1440px

- 相册版心接近 1400px。
- 宽画幅照片明显比当前固定四列更宽。
- 行内相框整体居中，行间无上下错位。
- 相框边界、白卡纸、照片内边界和右下阴影可分层辨认。
- 7 张照片形成自然的多行组合，最后一行居中且不被拉伸。

### 平板 820px

- 相框高度约 185px。
- 宽画幅不会挤出横向滚动。
- 每行整体居中，照片顺序不变。

### 手机 390px

- 相框高度约 140px，宽画幅必要时独占一行。
- 4:3 和竖幅照片保持可读，不产生横向溢出。
- 卡纸收窄但仍能看出相框层次。
- 展签与返回图标不被遮挡。

### 交互

- 点击照片仍打开对应的 PhotoSwipe 大图。
- 右上角没有明显关闭按钮。
- 箭头不遮挡照片，序号位于左上角，到首尾不循环。
- 键盘焦点和返回入口仍然可见、可操作。
