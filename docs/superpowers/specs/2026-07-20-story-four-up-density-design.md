# Story 相册四图密度与中心线对齐设计

## 背景

当前 Story 相册根据照片比例放大单图，横图可能占到半行，导致 2K 及以上屏幕一行只有两张图。目标应是保持摄影构图差异的同时，让宽屏相册恢复更高的信息密度：一行至少四张照片。

本规格覆盖并修正上一版相框尺寸方案；不改变照片顺序、图片资源、Story 自动加载或 PhotoSwipe 行为。

## 目标

- 在 2K 及以上桌面视口，一行至少容纳四张照片（照片数量足够时）。
- 横图仍然比竖图占用更宽的行内空间，竖图仍然体现更高的视觉比例。
- 每行保持水平居中；同行图框按垂直中心线对齐，而不是上边缘对齐。
- 相框与卡纸比当前略大，但不再通过放大单图目标面积来牺牲行密度。
- 故事标题、简介与相册继续使用同一个媒体版心。

## 设计决策

### 1. 有上限的比例分栏

保留当前 12 格虚拟列和 Flex 换行模型，但把桌面单图最大跨度限制为 3 格：

```text
ratio 约 0.67（竖图）  → 2/12
ratio 约 1.00–1.50     → 3/12
ratio 更宽             → 仍限制为 3/12
```

桌面使用较小的目标面积参数 `8`，再用 `maxSpan = 3` 做硬上限。这样四张普通横图最多正好占满 12 格；包含竖图时会留下自然的行内余量，由 `justify-content: center` 负责居中。该限制保证不会出现单张横图占半行、导致一行只剩两张的情况，同时保留竖图比横图窄、横图比竖图长的直觉差异。

平板继续使用 6 格布局和现有的两列密度，移动端继续使用当前竖图半列、横图整行的规则。

### 2. 行内中心线

将 `.story-album` 的交叉轴对齐设为 `align-items: center`，保留 `flex-wrap: wrap` 和 `justify-content: center`。Flex 自动分行不引入运行时 viewport 测量，也不手动创建行容器，避免 SSR/hydration 差异。

### 3. 相框材料

相框只做轻微增厚，避免材料比例再次挤压图片：

- 桌面：外框 `7px`，卡纸内缩约 `16–20px`。
- 平板：外框 `6px`，卡纸内缩约 `11–16px`。
- 移动端：外框 `6px`，卡纸内缩 `8px`。

保留原始宽高比、内侧边界、阴影和无圆角风格。

### 4. 宽屏版心与文字

故事页使用统一的 `--story-media-width`：

- 普通桌面：`min(1600px, calc(100vw - 96px))`。
- 4K 级宽屏（视口宽度 ≥ `3200px`）：`min(2200px, calc(100vw - 96px))`。
- 移动端和平板沿用现有窄屏版心。

相册、故事标题、简介段落都引用该变量，保持图片和文字的左右边界一致。

## 组件边界

### `StoryAlbum.vue`

为 `gridSpanForRatio` 增加可选的最大跨度参数，并在桌面调用时传入目标面积 `8` 与最大跨度 `3`。照片筛选、排序、资源地址、无障碍属性和 PhotoSwipe 逻辑不变。

### `_gallery.scss`

负责版心变量、文字宽度、Flex 对齐、相框材料和响应式断点。相册仍使用 CSS 原生 Flex，不增加运行时布局测量。

## 验证与验收

- 更新 StoryAlbum 的桌面 basis 测试，验证竖图约 2/12、横图约 3/12，且不会产生超过 3/12 的桌面跨度。
- 更新样式契约测试，验证 `align-items: center`、统一媒体版心及新的边框/卡纸尺寸。
- 在 2560px 和 3840px 视口检查：有足够照片时首行至少四张；每行整体居中；第一行横竖图框的垂直中心线一致。
- 在 1280px、820px 和移动端检查无横向溢出，移动端方向规则不变。
- 运行 `npm test`、`npm run docs:build` 和 `git diff --check`。

## 非目标

- 不改变 Gallery 首页卡片、图库 manifest、图片派生图或目录扫描逻辑。
- 不改变 PhotoSwipe 的打开、关闭、箭头、序号、循环和大图加载行为。
- 不恢复固定四列，也不引入基于屏幕尺寸的手工行分组。
