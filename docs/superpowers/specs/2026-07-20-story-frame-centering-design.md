# Story 相框尺寸与行内中心线对齐设计

## 背景

当前 Story 相册已经根据照片比例计算每张图的宽度，但行内使用 `align-items: flex-start`，所以同一行中的竖图和横图会从上边缘对齐，而不是以图片框的垂直中心线对齐。相框本身也需要再增加一档视觉重量。

本次调整只针对 Story 页面相册和故事页媒体版心，不改变照片顺序、图片资源、Gallery 首页或 PhotoSwipe 行为。

## 目标

- 相框整体再放大一档，让竖图和横图的比例差异更明确。
- 桌面、平板和移动端的外边框与卡纸内衬同步增加，保持相框层次清晰。
- 同一 Flex 行内的照片框以垂直中心线对齐；第一张竖图与第二张横图不再只对齐上边缘。
- 2K 屏保持更充足的左右留白，4K 屏允许媒体版心适度展开。
- 故事标题、简介与相册使用同一个媒体宽度变量，文字不再固定限制在 `620px`。

## 设计决策

### 1. 版心与文字宽度

使用统一的 `--story-media-width`：

- 普通桌面：`min(1600px, calc(100vw - 96px))`。
- 4K 级宽屏（视口宽度 ≥ `3200px`）：`min(2200px, calc(100vw - 96px))`。
- 移动端和平板继续使用现有断点版心，避免影响窄屏可读性。

`.story-album`、`PhotoStoryHeader` 和故事简介段落全部引用该变量。这样 2560px 左右的 2K 视口不会被过度铺满，而 3840px 左右的 4K 视口也不会留下过大的空墙。

### 2. 相框尺寸与材料

继续使用照片原始宽高比控制 `.story-album__frame` 的 `aspect-ratio`，通过增大比例布局的目标面积让相框尺寸整体上升一档：

- 桌面目标面积从 `20` 调到 `28`。
- 平板目标面积从 `8` 调到 `10`。
- 移动端沿用现有一列/半列方向规则。

材料尺寸调整为：

- 桌面：外框 `8px`，卡纸内缩约 `18–24px`。
- 平板：外框 `7px`，卡纸内缩约 `13–18px`。
- 移动端：外框 `6px`，卡纸内缩约 `8px`。

图片仍保持原始比例显示，不新增裁切、纹理或圆角。

### 3. 行内对齐

将相册 Flex 容器的交叉轴对齐从 `flex-start` 改为 `center`。Flex 自动换行和当前的行宽计算继续负责分行；每一行保留 `justify-content: center`，因此行内图片整体仍然居中，同时不同高度的图框以行的垂直中心线对齐。

不引入基于 viewport 的运行时测量或手工分组，避免 SSR/hydration 差异。

## 组件边界与数据流

### `StoryAlbum.vue`

只调整比例到布局目标面积的参数，继续输出照片原始比例和现有无障碍、缩略图、大图及 PhotoSwipe 数据。

### `_gallery.scss`

负责统一版心变量、文字宽度、Flex 行中心对齐、相框外框、卡纸和响应式材料尺寸。其它故事组件和非 Story 页面保持不变。

## 验证

- StoryAlbum 组件测试更新新的桌面/平板 flex basis 结果。
- 样式契约测试覆盖统一媒体宽度、相册 `justify-content: center`、行内 `align-items: center`、相框边框和卡纸尺寸。
- 使用本地 dev server 检查 2560px、3840px、1280px、820px 和移动端视口：2K 留白增加，4K 适度展开；每行水平居中；横竖图中心线对齐；文字与相册左右边界一致。
- 运行 `npm test`、`npm run docs:build` 和 `git diff --check`。

## 非目标

- 不改变 Gallery 首页卡片或故事图片目录/自动加载逻辑。
- 不改变 PhotoSwipe 的打开、关闭、箭头、序号和资源切换行为。
- 不新增图片资源或修改图库 manifest。
